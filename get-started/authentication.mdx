Every request you make to the Google REST API must be authenticated. Google uses bearer token authentication — you generate an API key in your account settings and include it in the `Authorization` header of each request. This page explains how to create keys, use them in your code, rotate or revoke them when needed, and handle the authentication errors you may encounter along the way.

## Generating an API Key

API keys are scoped to your user account and inherit the permissions of your workspace role. You can create multiple keys for different environments or integrations, and revoke any of them individually without affecting the others.

<Steps>

  <Step title="Open API Key Settings">
    Log in to your Google workspace and click your avatar in the top-right corner of the dashboard. Select **Settings** from the dropdown, then click **API Keys** in the left navigation menu.
  </Step>

  <Step title="Create a New Key">
    Click **Generate New Key**. In the dialog that appears, enter a descriptive name for the key — something that identifies its purpose and environment, such as `Production Backend` or `CI Pipeline`. Then click **Create**.

    <Note>
      You can optionally assign a **scope** to each API key to limit the operations it is allowed to perform. For example, a key scoped to `read:projects` can only read project data and cannot create, update, or delete resources. Scoped keys follow the principle of least privilege and are strongly recommended for integrations and automated pipelines.
    </Note>
  </Step>

  <Step title="Copy and Store Your Key Securely">
    After creation, Google displays the full API key **exactly once**. Copy it immediately and store it in a secure location such as a password manager, a secrets vault (e.g., HashiCorp Vault, AWS Secrets Manager), or your CI/CD platform's encrypted environment variables.

    <Warning>
      Never hardcode API keys in your source code, configuration files, or any file that is committed to version control. If a key is accidentally exposed in a public or private repository, revoke it immediately and generate a replacement. Tools like [git-secrets](https://github.com/awslabs/git-secrets) or [truffleHog](https://github.com/trufflesecurity/trufflehog) can help you scan for leaked credentials.
    </Warning>
  </Step>

</Steps>

## Authenticating Your Requests

Pass your API key in the `Authorization` header as a bearer token on every request. The header value must follow this exact format:

```
Authorization: Bearer YOUR_API_KEY
```

The following examples demonstrate how to authenticate a request to `GET /v1/resources` in three common environments:

<CodeGroup>

```bash cURL
curl --request GET \
  --url https://api.google.com/v1/resources \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json"
```

```javascript JavaScript (fetch)
const response = await fetch("https://api.google.com/v1/resources", {
  method: "GET",
  headers: {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
  },
});

if (!response.ok) {
  const error = await response.json();
  throw new Error(`API error ${response.status}: ${error.message}`);
}

const data = await response.json();
console.log(data);
```

```python Python (requests)
import requests

url = "https://api.google.com/v1/resources"
headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
}

response = requests.get(url, headers=headers)
response.raise_for_status()  # Raises an HTTPError for 4xx/5xx responses

data = response.json()
print(data)
```

</CodeGroup>

<Tip>
  Store your API key in an environment variable (e.g., `GOOGLE_API_KEY`) and reference it in your code rather than pasting the value directly. This keeps your code portable and your credentials out of plain sight.

  ```bash Terminal
  export GOOGLE_API_KEY="your_api_key_here"
  ```

  Then reference it in your application:

  ```python Python
  import os
  api_key = os.environ["GOOGLE_API_KEY"]
  ```
</Tip>

## Handling Authentication Errors

When authentication fails, the Google API returns a standard JSON error response with an HTTP status code and a machine-readable `code` field. The two most common authentication errors are described below.

<Tabs>
  <Tab title="401 Unauthorized">
    A `401 Unauthorized` response means the API key is missing, malformed, or has been revoked. Check that:

    - The `Authorization` header is present in your request.
    - The header value starts with `Bearer ` (note the space after `Bearer`).
    - The API key has not been revoked in **Settings → API Keys**.
    - You are not accidentally including extra whitespace or newline characters in the key value.

    **Example response:**

    ```json 401 Response
    {
      "error": {
        "code": "UNAUTHORIZED",
        "message": "Invalid or missing API key. Provide a valid bearer token in the Authorization header.",
        "status": 401
      }
    }
    ```
  </Tab>
  <Tab title="403 Forbidden">
    A `403 Forbidden` response means your API key is valid and recognized, but the key or its associated account does not have permission to perform the requested action. Common causes include:

    - The key was created with a **scope** that excludes the operation you are attempting (e.g., a read-only key attempting a `POST` or `DELETE` request).
    - Your workspace role (**Viewer**, **Member**, or **Admin**) does not grant access to the target resource.
    - You are trying to access a private project you have not been invited to.

    **Example response:**

    ```json 403 Response
    {
      "error": {
        "code": "FORBIDDEN",
        "message": "Your API key does not have permission to perform this action. Check the key's scope and your workspace role.",
        "status": 403
      }
    }
    ```

    To resolve a `403`, either adjust the key's scopes in **Settings → API Keys** or ask a workspace Admin to update your role.
  </Tab>
</Tabs>

## Rotating and Revoking Keys

You should rotate API keys periodically and revoke them immediately if you suspect they have been compromised.

**To rotate a key:**
1. Go to **Settings → API Keys**.
2. Click **Generate New Key** and create a replacement key with the same name and scopes.
3. Update all services and environment variables that use the old key with the new value.
4. Once every service is using the new key, click **Revoke** next to the old key.

**To revoke a key immediately:**
1. Go to **Settings → API Keys**.
2. Click **Revoke** next to the key you want to invalidate.
3. Confirm the action in the dialog. Revocation is instant and permanent — any request using the revoked key will immediately receive a `401 Unauthorized` response.

<Note>
  Revoking a key cannot be undone. If you revoke a key that is still in use by a running service, that service will begin returning authentication errors immediately. Always update your dependent services before revoking a key unless responding to a security incident.
</Note>
